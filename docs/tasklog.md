### 4-3 動作確認の結果

- 検証環境: PostgreSQL 17(サービス起動済み)、`node src/index.js` でサーバー起動
- POST /todos (正常系: title あり) → 201 ✅
- POST /todos (異常系: title なし) → 400 ✅ (`{"error":"title is required"}`)
- GET /todos (全件取得) → 200・配列で返却 ✅
- psql でDBを直接確認し、永続化されていることを確認 ✅

**気づき(予想外の動作):**
Git Bashからcurlで日本語のtitle(例:「Claude Code を試す」)を送信すると、DBに文字化けした状態で保存されてしまった。原因を切り分けるためPowerShellの`Invoke-RestMethod`でUTF-8エンコーディングを明示して同じリクエストを送ったところ、正常に日本語が保存されることを確認。→ アプリ側(pool.js/todos.js)のバグではなく、**Git Bash環境でcurlに日本語引数を渡す際のエンコーディング起因**と判断。今後日本語データをcurlで検証する際はPowerShellを使うか、UTF-8を明示する必要がある。

### 再確認(8/23)で残り項目を潰した

コミット履歴を見返したら、ci.yml/deploy.ymlの理解は既に済んでいたので、実質残っていたのは以下4項目だった。

- **`todos.js`の各エンドポイント**: 
・クエリパラメータは常に文字列で渡ってくる
・PATCHの`COALESCE`が「値が無ければ元のまま残す」ためのものである
・try/catchが無いとDB接続失敗時にサーバーが応答不能になる
- **`.env`をGitに上げない理由**: 
機密情報(パスワード・APIキー)の漏洩を防ぐため。`.
・gitignore`にコメントを書く際、`//`ではなく`#`が正しい記法
- **AAAパターンで新規テストケース**: `PATCH /todos/:id`に「titleが空白のみなら400を返す」テストが抜けていたのに気づき、既存のPOST版を参考に自分で1件追加。`npx jest`で14件全パス確認
- **カバレッジの意味**: `npm run test:coverage`を実行し、行カバレッジ84.9%・分岐カバレッジ100%という結果になった理由(各エンドポイントのcatchブロックが未実行だった一方、if分岐は正常系・異常系のテストで両方通っていた)を理解し、`jest.config.js`にコメントを追記

- 最終採点: 13項目中 13個(全項目クリア)
